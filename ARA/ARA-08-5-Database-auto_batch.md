# قاعدة البيانات (Database) - نمط الدُفعة/التجميعة الآلي (Automatic Batch Mode)

يعمل نمط الدُفعة الآلي (Automatic batch mode) حصرياً مع مكتبة العميل لقاعدة بيانات PostgreSQL بالإصدار 14 أو أحدث، بينما يتجاهله إطار العمل في الحالات الأخرى. وقبل الحديث عن المعالجة التجميعية الآلية، دعنا نفهم أولاً نمط الأنبوب (Pipeline mode).

### نمط الأنبوب (Pipeline mode)

بدءاً من الإصدار 14 لـ PostgreSQL، توفر مكتبة العميل الخاصة بها واجهة لنمط الأنبوب (Pipelining mode). وفي هذا النمط، يمكن إرسال طلبات SQL الجديدة مباشرة إلى الخادم دون الحاجة لانتظار إرجاع نتيجة الطلب السابق (وهو ما يتوافق مع مفهوم HTTP pipelining)، ولمزيد من التفاصيل يُرجى الرجوع إلى وثائق [Pipeline mode](https://www.postgresql.org/docs/current/libpq-pipeline-mode.html). يساعد هذا النمط بشكل كبير في تحسين الأداء، حيث يتيح لعدد أقل من اتصالات قاعدة البيانات دعم قدر أكبر من الطلبات المتزامنة (Concurrent requests).
بدأ Drogon في دعم هذا النمط بدءاً من الإصدار 1.7.6، حيث يتحقق تلقائياً مما إذا كانت مكتبة `libpq` تدعم نمط الأنبوب، وفي حال دعمها، فإن جميع الطلبات المرسلة عبر `DbClient` الخاص بـ Drogon تعمل بنمط الأنبوب تلقائياً.

### نمط الدُفعة الآلي (Automatic batch mode)

بشكل افتراضي، بالنسبة للعملاء غير المعتمدين على المعاملات البرمجية (Non-transactional clients)، ينشئ Drogon نقاط مزامنة (Synchronization points) لكل طلب SQL، أي أن كل جملة SQL منفردة تُعامل كـ معاملة ضمنية (Implicit transaction)، مما يضمن استقلالية طلبات SQL عن بعضها البعض، ويجعل نمط الأنبوب والنمط العادي يتطابقان تماماً من منظور المطور.

ومع ذلك، فإن إنشاء نقطة مزامنة لكل جملة SQL يتطلب استهلاكاً إضافياً لموارد المعالجة (Performance overhead)، لذا يوفر Drogon نمط الدُفعة الآلي الذي ينشئ نقطة مزامنة واحدة بعد عدة جمل SQL بدلاً من إنشائها بعد كل جملة منفردة. وتكون قواعد إنشاء نقاط المزامنة داخل الاتصال نفسه كالتالي:

- إنشاء نقطة مزامنة وجوباً بعد آخر جملة SQL داخل حلقة الأحداث (EventLoop).
- إنشاء نقطة مزامنة بعد أي جملة SQL تقوم بالكتابة في قاعدة البيانات.
- إنشاء نقطة مزامنة بعد جمل SQL الكبيرة (Big sql).
- إنشاء نقطة مزامنة عندما يصل عدد جمل SQL المتتالية بعد آخر نقطة مزامنة إلى الحد الأقصى المسموح به.

تنبيه: جمل SQL الواقعة بين نقطتي مزامنة داخل الاتصال نفسه تنتمي إلى المعاملة الضمنية نفسها. ولا يوفر Drogon واجهة صريحة لفتح نقاط المزامنة أو إغلاقها، لذا قد تكون جمل SQL هذه غير مرتبطة منطقياً ببعضها البعض، ولكن نظراً لوجودها داخل المعاملة نفسها، فإنها ستؤثر على بعضها البعض. بناءً عليه، لا يُعد هذا النمط نمطاً آمناً تماماً، وينطوي على الإشكاليات التالية:

- فشل أي جملة SQL سيتسبب في التراجع عن جمل SQL السابقة لها والواقعة بعد آخر نقطة مزامنة، دون أن يتلقى المطور أي إشعار بذلك نظراً لعدم استخدام معاملة صريحة.
- فشل أي جملة SQL سيتسبب في إرجاع الفشل لجميع جمل SQL التالية لها وقبل نقطة المزامنة القادمة.
- يعتمد تحديد عمليات الكتابة في قاعدة البيانات على مطابقة بسيطة للكلمات المفتاحية (مثل insert و update وغيرها)، وهو ما لا يغطي كافة الحالات، مثل حالة استدعاء الإجراءات المخزنة (Stored procedures) عبر جمل select. لذلك، ورغم سعي Drogon للحد من الآثار السلبية لنمط الدُفعة الآلي، إلا أنه لا يُعد آمناً تماماً.

بناءً عليه، يساعد نمط الدُفعة الآلي في تحسين الأداء ولكنه ليس آمناً بنسبة 100%. ويبقى قرار استخدامه ونطاق تطبيقه مسؤولية المطور، على سبيل المثال، لتنفيذ جمل SQL المخصصة للقراءة فقط عبر `DbClient` بنمط الدُفعة الآلي.

> **ملاحظة:** حتى جمل SQL المخصصة للقراءة فقط قد تتسبب أحياناً في فشل المعاملة (مثل تجاوز مهلة الاستعلام select timeout)، مما يؤدي إلى تأثر جمل SQL التالية لها وفشلها أيضاً (وهو ما قد لا يكون مقبولاً للمطور نظراً لعدم وجود رابط منطقي بينها في التطبيق). لذا، وبشكل دقيق، يجب حصر حالات استخدام نمط الدُفعة الآلي في استعلامات البيانات المخصصة للقراءة فقط وغير الحساسة. ويوصى بأن ينشئ المطور كائن `DbClient` منفصلاً بنمط الدُفعة الآلي لمثل هذه الجمل. بالطبع، من السهل إدراك أن كائنات المعاملات (Transaction objects) الناتجة عن `DbClient` بنمط الدُفعة الآلي تكون آمنة تماماً للاستخدام.

### تفعيل نمط الدُفعة الآلي (Enable automatic batch mode)

عند استخدام الواجهة `newPgClient` لإنشاء عميل، اضبط المعامل الثالث على `true` لتفعيل نمط الدُفعة الآلي.
وعند استخدام ملف الإعدادات لإنشاء العميل، اضبط الخيار `auto_batch` على `true` لتفعيل نمط الدُفعة الآلي لهذا العميل.
