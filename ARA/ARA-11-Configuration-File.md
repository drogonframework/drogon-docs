# ملف الإعدادات (Configuration File)

يمكنك التحكم في السلوكيات المختلفة لخادم Http عبر ضبط المعاملات المتنوعة من خلال الواجهات المتعددة لكائن `DrogonAppFramework`. ومع ذلك، يُعد استخدام ملف الإعدادات طريقة أفضل للأسباب التالية:

- استخدام ملف الإعدادات بدلاً من الكود المصدري يحدد سلوك التطبيق أثناء وقت التشغيل (Runtime) بدلاً من وقت التجميع (Compile time)، وهو بلا شك أسلوب أكثر سهولة ومرونة.
- استخدام ملف الإعدادات يجعل الملف الرئيسي (`main`) أكثر إيجازاً ونظافة.

بناءً على هذه الفوائد الإضافية، يُوصى مطورو التطبيقات باستخدام ملفات الإعدادات لتكوين المعاملات المختلفة للتطبيق.

يمكن تحميل ملف الإعدادات ببساطة شديدة عبر استدعاء الواجهة `loadConfigFile()` قبل استدعاء الواجهة `run()`. ومعامل الدالة `loadConfigFile()` هو اسم ملف الإعدادات، على سبيل المثال:

```c++
int main()
{
    drogon::app().loadConfigFile("config.json");
    drogon::app().run();
}
```

يقوم البرنامج أعلاه بتحميل ملف الإعدادات `config.json` ثم يختبر ويشغل التطبيق. ويمكن إعداد منفذ الاستماع، ومخرجات السجلات، وإعدادات قواعد البيانات وما إلى ذلك عبر ملف الإعدادات. في الواقع، يمكن لهذا البرنامج أن يكون الكود الكامل تقريباً للملف الرئيسي للتطبيق.

### تفاصيل ملف الإعدادات (Configuration File Details)

يوجد مثال لملف الإعدادات في المستوى الأعلى من مجلد المصدر باسم `config.example.json`. وإذا استخدمت الأمر `drogon_ctl create project` لإنشاء مشروع، فستجد أيضاً الملف `config.json` بالمحتوى نفسه داخل مجلد المشروع. لذا، لا تحتاج أساساً إلى إنشاء ملف إعدادات جديد، بل يمكنك إجراء بعض التعديلات على هذا الملف لإكمال تهيئة تطبيق الويب.

الملف بصيغة `JSON` ويدعم التعليقات. ويمكنك تعليق عناصر الإعداد غير المطلوبة باستخدام رموز تعليقات C++ مثل `/* */` و `//`.

بعد تعليق خيار إعداد معين، يقوم إطار العمل بتهيئته بالقيم الافتراضية. ويمكن العثور على القيمة الافتراضية لكل خيار داخل التعليقات المرفقة في ملف الإعدادات.

### الصيغ المدعومة (Supported Formats)
* JSON
* YAML (يتطلب تثبيت مكتبة `yaml-cpp` لتوفير محلل ملفات YAML).

- ### SSL

  خيار SSL مخصص لإعداد ملفات SSL الخاصة بلمستمعي خدمة HTTPS كالتالي:

  ```json
    "ssl": {
      "cert": "../../trantor/trantor/tests/server.pem",
      "key": "../../trantor/trantor/tests/server.pem",
      "conf":[
        ["Options", "Compression"],
        ["min_protocol", "TLSv1.2"]
      ]
    }
  ```

  حيث يمثل `cert` مسار ملف الشهادة، و `key` مسار ملف المفتاح الخاص. وإذا كان الملف يحتوي على الشهادة والمفتاح الخاص معاً، فيمكن جعل المسارين متطابقين. والملف يتبع صيغة ترميز PEM.

  الخيار `conf` عبارة عن خيارات SSL اختيارية تُمرر مباشرة إلى [SSL_CONF_cmd](https://www.openssl.org/docs/manmaster/man3/SSL_CONF_cmd.html) للسماح بتكوين التشفير على مستوى منخفض. ويجب أن تكون الخيارات عبارة عن مصفوفات تحتوي على عنصر واحد أو عنصرين.

- ### المستمعون (listeners)

  كما يتضح من الاسم، خيار `listeners` مخصص لإعداد مستمعي شبكة الاتصال لتطبيق الويب. وهو من نوع مصفوفة JSON، ويمثل كل كائن JSON مستمعاً واحداً. وفيما يلي التكوين التفصيلي:

  ```json
  "listeners": [
      {
        "address": "0.0.0.0",
        "port": 80,
        "https": false
      },
      {
        "address": "0.0.0.0",
        "port": 443,
        "https": true,
        "cert": "",
        "key": ""
      }
    ]
  ```

  ومنها:

  - `address`: نوع نصي يحدد عنوان IP المراد الاستماع إليه. وإذا لم يتوفر هذا الخيار، تُستخدم القيمة الافتراضية `"0.0.0.0"`.
  - `port`: خيار من نوع عدد صحيح يحدد المنفذ المراد الاستماع إليه، ويجب أن يكون رقم منفذ صالحاً، ولا توجد له قيمة افتراضية.
  - `https`: قيمة منطقية تعبر عما إذا كان سيتم استخدام https، والقيمة الافتراضية هي `false` والتي تعني استخدام http.
  - `cert` و `key`: من النوع النصي، وتكونان صالحتين عندما يكون `https` بـ `true` لتحديد الشهادة والمفتاح الخاص لـ https. والقيمة الافتراضية هي نص فارغ، مما يعني استخدام الشهادة والمفتاح الخاص المحددين في الخيار العام `ssl`.

- ### عملاء قاعدة البيانات (db_clients)

  يُستخدم هذا الخيار لتكوين عميل قاعدة البيانات، وهو من نوع مصفوفة JSON. ويمثل كل كائن JSON عميل قاعدة بيانات منفصلاً. والتكوين التفصيلي كالتالي:

  ```json
    "db_clients":[
      {
        "name":"",
        "rdbms": "postgresql",
        "host": "127.0.0.1",
        "port": 5432,
        "dbname": "test",
        "user": "",
        "passwd": "",
        "is_fast": false,
        "connection_number": 1,
        "filename": ""
      }
    ]
  ```

  ومنها:

  - `name`: نوع نصي يمثل اسم العميل، والقيمة الافتراضية هي `"default"`. والاسم هو علامة يستعين بها المطور للحصول على عميل قاعدة البيانات من إطار العمل، وإذا كان هناك عدة عملاء، يجب أن يكون حقل الاسم مختلفاً بينها.
  - `rdbms`: نص يحدد نوع خادم قاعدة البيانات. ويدعم حالياً `"postgresql"` و `"mysql"` و `"sqlite3"`، وهو غير حساس لحالة الأحرف.
  - `host`: نص يمثل عنوان خادم قاعدة البيانات، وتُعد `localhost` هي القيمة الافتراضية.
  - `port`: عدد صحيح يمثل رقم منفذ خادم قاعدة البيانات.
  - `dbname`: نص يحدد اسم قاعدة البيانات.
  - `user`: نص يحدد اسم المستخدم.
  - `passwd`: نص يحدد كلمة المرور.
  - `is_fast`: قيمة منطقية، افتراضياً `false` لبيان ما إذا كان العميل عبارة عن [FastDbClient](/ARA/ARA-08-4-Database-FastDbClient).
  - `connection_number`: عدد صحيح يحدد عدد الاتصالات بخادم قاعدة البيانات (1 على الأقل، والقيمة الافتراضية هي 1 أيضاً)، ويؤثر على أداء التزامن لقراءة البيانات وكتابتها. وإذا كان `is_fast` بـ `true` تكون هذه القيمة هي عدد الاتصالات لكل حلقة أحداث، وإلا فهي إجمالي عدد جميع الاتصالات.
  - `filename`: اسم ملف قاعدة البيانات الخاص بـ sqlite3.

- ### عدد خيوط التنفيذ (threads_num)

  خيار فرعي تابع لخيار `app`، وهو عدد صحيح بقيمة افتراضية 1، ويحدد عدد خيوط الإدخال/الإخراج (IO threads)، وله تأثير واضح على تزامن الشبكة. وهذا الرقم ليس الأكبر هو الأفضل دائماً، فمن يفهم مبدأ الإدخال/الإخراج اللامُعَطِّل يعلم أن هذه القيمة يجب أن تطابق عدد المعالجات التي يتوقع أن تشغلها عمليات الإدخال/الإخراج للشبكة. وإذا ضُبطت القيمة على 0، فسيصبح عدد خيوط الإدخال/الإخراج مساوياً لعدد جميع النوى الصلبة للمعالج.

  ```json
  "threads_num": 16,
  ```

  يوضح المثال أعلاه أن الإدخال/الإخراج للشبكة يستخدم 16 خيط تنفيذ ويمكنه العمل على ما يصل إلى 16 نوات معالج تحت ظروف الحمل الفائق.

- ### الجلسة (Session)

  الخيارات المتعلقة بالجلسات هي أيضاً خيارات فرعية تابعة لخيار `app`، وتتحكم في تفعيل الجلسات ومهلة انتهائها، مثل:

  ```json
  "enable_session": true,
  "session_timeout": 1200,
  ```

  ومنها:

  - `enable_session`: قيمة منطقية تحدد ما إذا كانت الجلسات مُفعلة، وافتراضياً تكون `false`. وإذا كان العميل لا يدعم الكعكات (Cookies)، فاعمد إلى ضبطها على `false` لأن إطار العمل سينشئ جلسة جديدة لكل طلب لا يحتوي على كعكة جلسة، مما يؤدي إلى هدر الموارد وانخفاض الأداء دون داعٍ.
  - `session_timeout`: عدد صحيح يحدد فترة مهلة الجلسة بالثواني، والقيمة الافتراضية هي 0 وتدعى الصلاحية الدائمة. ويعمل فقط إذا كان `enable_session` بـ `true`.

- ### المجلد الرئيسي للمستندات (document_root)

  خيار فرعي لـ `app` من النوع النصي يحدد مسار المستندات المناظر للمجلد الرئيسي لـ Http، وهو المسار الجذر لتنزيل الملفات الثابتة. والقيمة الافتراضية هي `"./"` لبيان المسار الحالي لصلب تشغيل البرنامج، مثل:

  ```json
  "document_root": "./",
  ```

- ### مسار الرفع (upload_path)

  خيار فرعي لـ `app` من النوع النصي يمثل المسار الافتراضي لرفع الملفات. والقيمة الافتراضية هي `"uploads"`. وإذا كانت القيمة لا تبدأ بـ `/` أو `./` أو `../` وليست `.` أو `..` فإن هذا المسار يكون مساراً نسبياً مدخلاً بعد `document_root` السابق، وإلا فهو مسار مطلق أو مسار نسبي للمجلد الحالي، مثل:

  ```json
  "upload_path":"uploads",
  ```

- ### الحجم الأقصى لمتن الطلب (client_max_body_size)

  كائن فرعي لـ `app` من النوع النصي يمثل الحجم الأقصى الإجمالي لمتن الطلب.
  يمكنك استخدام اللواحق `k` و `m` و `g` لتحديد الكيلوبايت أو الميجابايت أو الجيجابايت (byte * 1024)، وفي أنظمة 64 بت يمكنك استخدام `t` للتيرابايت. واللواحق يمكن أن تكون بأحرف صغيرة أو كبيرة.

  ```json
  "client_max_body_size": "10M",
  ```

- ### الحجم الأقصى لمتن الطلب في الذاكرة (client_max_memory_body_size)

  كائن فرعي لـ `app` من النوع النصي يمثل الحد الأقصى لحجم المخزن المؤقت لتخزين متن الطلب قبل التخزين المؤقت في ملف.
  يمكنك استخدام اللواحق `k` و `m` و `g` لتحديد الكيلوبايت أو الميجابايت أو الجيجابايت، وفي أنظمة 64 بت يمكنك استخدام `t`.

  ```json
  "client_max_memory_body_size": "50K"
  ```

- ### أنواع الملفات (file_types)

  خيار فرعي لـ `app` عبارة عن مصفوفة من النصوص بقيم افتراضية كالتالي تحدد أنواع تنزيل الملفات الثابتة المدعومة بواسطة إطار العمل. وإذا كان امتداد الملف الثابت المطلوب خارج هذه الأنواع، فسيُرجع إطار العمل خطأ 404.

  ```json
  "file_types": [
        "gif",
        "png",
        "jpg",
        "js",
        "css",
        "html",
        "ico",
        "swf",
        "xap",
        "apk",
        "cur",
        "xml"
      ],
  ```

- ### أنواع MIME

  خيار فرعي لـ `app` عبارة عن قاموس من نصوص إلى نصوص أو مصفوفة نصوص. يحدد كيفية ربط امتدادات الملفات بأنواع MIME الجديدة (أي لتلك التي لا يتعرف عليها افتراضياً) عند إرسال الملفات الثابتة. لاحظ أن هذا الخيار يسجل فقط أنواع MIME، وسيستمر إطار العمل في إرسال خطأ 404 إذا لم يكن الامتداد ضمن `file_types` المذكورة أعلاه.

  ```json
  "mime" : {
    "text/markdown": "md",
    "text/gemini": ["gmi", "gemini"]
  }
  ```

- ### التحكم في عدد الاتصالات (Connection number control)

  الخيارات الفرعية لـ `app` تتضمن خيارين كالتالي:

  ```json
  "max_connections": 100000,
  "max_connections_per_ip": 0,
  ```

  ومنها:

  - `max_connections`: عدد صحيح، والقيمة الافتراضية هي 100000، وتعبر عن الحد الأقصى لاتصالات التزامن المتزامنة. وعندما يصل عدد الاتصالات التي يحتفظ بها الخادم إلى هذا الرقم، سيتم رفض طلبات اتصال TCP الجديدة مباشرة.
  - `max_connections_per_ip`: عدد صحيح، والقيمة الافتراضية هي 0، وتحدد الحد الأقصى لعدد الاتصالات لعنوان IP لعميل واحد، و 0 تعني عدم وجود حد.

- ### خيارات السجلات (Log options)

  عنصر فرعي لـ `app` عبارة عن كائن JSON يتحكم في سلوك مخرجات السجلات كالتالي:

  ```json
  "log": {
        "log_path": "./",
        "logfile_base_name": "",
        "log_size_limit": 100000000,
        "log_level": "TRACE"
      },
  ```

  ومنها:

  - `log_path`: نص، والقيمة الافتراضية هي نص فارغ يحدد المسار الذي يُحفظ فيه ملف السجل. وإذا كان نصاً فارغاً، تخرج جميع السجلات إلى المخرج القياسي (Standard output).
  - `logfile_base_name`: نص يحدد الاسم الأساسي (`basename`) لملف السجل. والقيمة الافتراضية هي نص فارغ مما يعني أن الاسم الأساسي سيكون `drogon`.
  - `log_size_limit`: عدد صحيح بالبايت. والقيمة الافتراضية هي 100000000 (100 ميجابايت). وعندما يصل حجم ملف السجل إلى هذه القيمة، يتم التبديل إلى ملف سجل جديد.
  - `log_level`: نص، والقيمة الافتراضية هي `"DEBUG"` لبيان أدنى مستوى لمخرجات السجل. والخيارات المتاحة من الأدنى للأعلى هي: `"TRACE"` و `"DEBUG"` و `"INFO"` و `"WARN"`، حيث يكون مستوى TRACE صالحاً فقط عند التجميع في وضع DEBUG.

  > **ملاحظة: يستخدم سجل ملفات Drogon هيكل مخرجات لامُعَطِّل يمكنه تحقيق خروج سجلات يصل إلى ملايين الأسطر في الثانية ويمكن استخدامه بثقة تامّة.**

- ### التحكم في التطبيق (Application control)

  خيارات فرعية لـ `app` تتضمن خيارين كالتالي:

  ```json
      "run_as_daemon": false,
      "relaunch_on_error": false,
  ```

  ومنها:

  - `run_as_daemon`: قيمة منطقية، والقيمة الافتراضية هي `false`. وعندما تكون `true` سيعمل التطبيق كعملية فرعية للعملية رقم 1 في هيئة خادم خلفية (Daemon) يعمل في خلفية النظام.
  - `relaunch_on_error`: قيمة منطقية، والقيمة الافتراضية هي `false`. وعندما تكون `true` يعيد التطبيق تشغيل نفسه تلقائياً عند حدوث خطأ.

- ### استخدام sendfile (use_sendfile)

  خيار فرعي لـ `app` بقيمة منطقية يحدد ما إذا كان سيتم استخدام استدعاء النظام `sendfile` الخاص بنظام Linux عند إرسال الملفات. والقيمة الافتراضية هي `true`. واستخدام `sendfile` يرفع كفاءة الإرسال ويقلل استهلاك الذاكرة للملفات الكبيرة، كما يلي:

  ```json
  "use_sendfile": true,
  ```

  > **ملاحظة: حتى إذا كان هذا الخيار مفادُه true، فلن يُستخدم استدعاء النظام sendfile في كل الحالات لأن استخدام sendfile للملفات الصغيرة ليس بالضرورة اقتصادي الأداء، وسيقرر إطار العمل ما إذا كان سيعتمده وفقاً لاستراتيجية التحسين الخاصة به.**

- ### استخدام الضغط (use_gzip)

  خيار فرعي لـ `app` بقيمة منطقية وقيمة افتراضية `true` يحدد ما إذا كان متن استجابة Http سيستخدم النقل المضغوط. وعندما يكون `true` يُستخدم الضغط في الحالات التالية:

  - العميل يدعم ضغط gzip.
  - متن Http من النوع النصي (Text type).
  - طول متن الاستجابة أكبر من قيمة معينة.

  مثال التكوين كالتالي:

  ```json
  "use_gzip": true,
  ```

- ### زمن التخزين المؤقت للملفات الثابتة (static_files_cache_time)

  خيار فرعي لـ `app` برقم صحيح يحدد بالثواني زمن التخزين المؤقت للملفات الثابتة، أي أنه عند تكرار الطلب على الملف خلال هذه الفترة، يُرجع إطار العمل الاستجابة مباشرة من الذاكرة دون القراءة من نظام الملفات. والقيمة الافتراضية هي 5 ثوانٍ، و 0 تعني التخزين المؤقت دائماً (القراءة من نظام الملفات مرة واحدة فقط، ويُستخدم بحذر)، والقيمة السالبة تعني عدم التخزين المؤقت، كما يلي:

  ```json
  "static_files_cache_time": 5,
  ```

- ### خريطة المتحكمات البسيطة (simple_controllers_map)

  خيار فرعي لـ `app` عبارة عن مصفوفة كائنات JSON، يمثل كل منها ربطاً من مسار Http إلى `HttpSimpleController`. وهذا التكوين مجرد خيار بديل وليس شرطاً لتكوينه هنا، راجع دليل [المتحكم البسيط (HttpSimpleController)](/ARA/ARA-04-1-Controller-HttpSimpleController).
  التكوين التفصيلي كالتالي:

  ```json
  "simple_controllers_map": [
        {
          "path": "/path/name",
          "controller": "controllerClassName",
          "http_methods": ["get","post"],
          "filters": ["FilterClassName"]
        }
      ],
  ```

  ومنها:

  - `path`: نص يمثل مسار Http.
  - `controller`: نص يمثل اسم فئة `HttpSimpleController`.
  - `http_methods`: مصفوفة نصوص تمثل طرق Http المدعومة. والطلبات الخارجه عن هذه القائمة سيتم تصفيتها مع إرجاع خطأ 405.
  - `filters`: مصفوفة نصوص تمثل قائمة الفلاتر على المسار، راجع دليل [البرمجيات الوسيطة والفلاتر (Middleware and Filter)](/ARA/ARA-05-Middleware-and-Filter).

- ### التحكم في مهلة الاتصال الخامل (Idle connection timeout control)

  خيار فرعي لـ `app` برقم صحيح يحدد مهلة الخمول بالثواني، والقيمة الافتراضية هي 60. وعندما يتجاوز الاتصال هذا الوقت دون أي قراءة أو كتابة، يُقطع الاتصال قسراً، كالتالي:

  ```json
  "idle_connection_timeout": 60
  ```

- ### التحميل الديناميكي للعروض (Dynamic view loading)

  خيارات فرعية لـ `app` تتحكم في تفعيل مسار العروض الديناميكية، ولديها خياران كالتالي:

  ```json
  "load_dynamic_views": true,
  "dynamic_views_path": ["./views"],
  ```

  ومنها:

  - `load_dynamic_views`: قيمة منطقية، والقيمة الافتراضية هي `false`. وعندما تكون `true` يبحث إطار العمل عن ملفات العرض في مسار العروض ويقوم بتجميعها ديناميكياً إلى ملفات `.so` ثم تحميلها في التطبيق. وعند تغيير أي ملف عرض، سيؤدي ذلك أيضاً إلى إعادة التجميع والتحميل تلقائياً.
  - `dynamic_views_path`: مصفوفة نصوص يمثل كل منها مسار البحث عن العروض الديناميكية. وإذا كانت قيمة المسار لا تبدأ بـ `/` أو `./` أو `../` وليست `.` أو `..` فإن هذا المسار يكون مساراً نسبياً مدخلاً بعد `document_root` السابق، وإلا فهو مسار مطلق أو مسار نسبي للمجلد الحالي.

  راجع دليل [العرض (View)](/ARA/ARA-06-View).

- ### حقل ترويسة الخادم (Server header field)

  خيار فرعي لـ `app` يحدد حقل ترويسة الخادم لجميع الاستجابات المرسلة بواسطة إطار العمل. والقيمة الافتراضية هي نص فارغ. وعندما يكون هذا الخيار فارغاً، يولد إطار العمل تلقائياً حقل ترويسة على الصورة `Server: drogon/version string` كالتالي:

  ```json
  "server_header_field": ""
  ```

- ### طلبات الاتصال المستمر (Keepalive requests)

  يحدد الخيار `keepalive_requests` الحد الأقصى لعدد الطلبات التي يمكن خدمتها عبر اتصال مستمر واحد (Keep-alive connection). وبعد الوصول للحد الأقصى من الطلبات، يتم إغلاق الاتصال. والقيمة الافتراضية 0 تعني عدم وجود حد، كالتالي:

  ```json
  "keepalive_requests": 0
  ```

- ### طلبات النمط الأنبوبي (Pipelining requests)

  يحدد الخيار `pipelining_requests` الحد الأقصى لعدد الطلبات غير المعالجة التي يمكن تخزينها مؤقتاً في ذاكرة التخزين المؤقت للأنبوب (Pipelining buffer). وبعد الوصول للحد الأقصى للطلبات، يتم إغلاق الاتصال. والقيمة الافتراضية 0 تعني عدم وجود حد. ولمزيد من التفاصيل حول النمط الأنبوبي، يُرجى الرجوع إلى `rfc2616-8.1.1.2` كالتالي:

  ```json
  "pipelining_requests": 0
  ```
