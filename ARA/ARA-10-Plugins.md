# الإضافات (Plugins)

تُستخدم الإضافات لمساعدة المطورين في بناء تطبيقات معقدة. وفي Drogon، يتم بناء جميع الإضافات وتثبيتها داخل التطبيق بناءً على ملف الإعدادات. وتكون الإضافات في Drogon ذات نسخة منفردة (Single-instance)، ويمكن للمطورين تنفيذ أي وظيفة يريدونها باستخدام الإضافات.

عندما ينفذ Drogon الواجهة `run()`، فإنه يقوم بإنشاء كائنات الإضافات واحدة تلو الأخرى وفقاً لملف الإعدادات ويستدعي الواجهة `initAndStart()` الخاصة بكل منها.

### التكوين والإعداد (Configuration)

يتم إعداد الإضافات عبر ملف التكوين، على سبيل المثال:

```json
    "plugins": [
        {
        //name: اسم الفئة (Class name) الخاصة بالإضافة
        "name": "DataDictionary",
        //dependencies: الإضافات التي تظبط هذه الإضافة كاعتمادية عليها. يمكن إلغاء تعليقها حسب الحاجة
        "dependencies": [],
        //config: إعدادات الإضافة. كائن JSON هذا هو المعامل المستخدم لتهيئة الإضافة.
        //يمكن إلغاء تعليقها حسب الحاجة
        "config": {
        }
        }],
```

يتضح أن هناك ثلاثة خيارات إعداد لكل إضافة:

- **name**: هو اسم الفئة للإضافة (بما في ذلك مساحة الأسماء/نطاق الأسماء Namespace). وسيُنشئ إطار العمل كائناً من الإضافة بناءً على اسم الفئة. وإذا تم تعليق هذا الخيار، ستُعطل الإضافة.
- **dependencies**: هي قائمة بأسماء الإضافات الأخرى التي تُعتمد عليها. ينشئ إطار العمل جميع الإضافات ويهيئها بترتيب معين، حيث يعطي الأولوية لإنشاء وتهيئة الإضافات التي تعتمد عليها الإضافات الأخرى. وعند إنهاء البرنامج، يُغلق إطار العمل الإضافات ويدمرها بترتيب عكسي. يُرجى ملاحظة أن الاعتماديات الدائرية (Circular dependencies) بين الإضافات ممنوعة تماماً، وسيقوم Drogon بتقديم إشعار بالخطأ وإنهاء البرنامج فوراً إذا اكتشف وجود اعتمادية دائرية. وإذا تم تعليق هذا الخيار، تكون قائمة الاعتماديات فارغة.
- **config**: هو كائن JSON المُستخدم لتهيئة الإضافة، ويُمرر كمعامل مدخلات إلى الواجهة `initAndStart()` الخاصة بالإضافة. وإذا تم تعليق هذا الخيار، يكون كائن JSON الممرر إلى الواجهة `initAndStart` عبارة عن كائن فارغ.

### التعريف (Definition)

يجب أن ترث الإضافات المعرفة من قبل المطور من قالب الفئة `drogon::Plugin`، ويكون معامل القالب هو نوع الإضافة نفسه، مثل التعريف التالي:

```c++
class DataDictionary : public drogon::Plugin<DataDictionary>
{
public:
    virtual void initAndStart(const Json::Value &config) override;
    virtual void shutdown() override;
    ...
};
```

يمكن إنشاء الملفات المصدرية للإضافة عبر الأمر `drogon_ctl`:

```shell
drogon_ctl create plugin <[namespace::]class_name>
```

### الحصول على الكائن (Getting Instance)

يتم إنشاء كائن الإضافة بواسطة Drogon، ويمكن للمطور الحصول على كائن الإضافة عبر واجهة Drogon التالية:

```c++
template <typename T> T *getPlugin();
```

أو

```c++
PluginBase *getPlugin(const std::string &name);
```

ومن الواضح أن الطريقة الأولى أكثر راحة وسهولة. على سبيل المثال، يمكن الحصول على الإضافة `DataDictionary` المذكورة أعلاه كالتالي:

```c++
auto *pluginPtr=app().getPlugin<DataDictionary>();
```

لاحظ أنه من الأفضل الحصول على الإضافة بعد استدعاء الواجهة `run()` لإطار العمل، وإلا فستحصل على كائن إضافة غير مهيأ (ولا يؤدي ذلك بالضرورة إلى خطأ، طالما تتأكد من استخدام الإضافة بعد اكتمال تهيئتها). بالطبع، وبما أن الإضافات تُهيأ وفقاً لترتيب الاعتماديات، فلا يوجد أي إشكال في الحصول على كائن إضافة أخرى داخل الواجهة `initAndStart()`.

### دورة الحياة (Life Cycle)

تُهيأ جميع الإضافات داخل الواجهة `run()` لإطار العمل وتُدمر عند الخروج من التطبيق. لذلك، فإن دورة حياة الإضافة تطابق تقريباً دورة حياة التطبيق نفسه، ولهذا السبب لا تحتاج الواجهة `getPlugin()` إلى إرجاع مؤشر ذكي (Smart pointer).
